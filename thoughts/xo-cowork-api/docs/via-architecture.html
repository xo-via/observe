3. How an event flows

One user message walks the whole loop. Time runs top to bottom.

  T+0     HUMAN
            │  sends chat: "what's up with acme?"
            ▼
  T+0.1   cowork-api receives, appends to life/stream.jsonl
          as {"source":"chat","kind":"user.message","text":"..."}
            │
            ▼
  T+0.1   cowork-api spawns VIA subprocess
            │  cwd: ~/xo-projects/via/
            │  claude_code with --mcp-config (cowork local MCP)
            │
            ▼
  T+0.2   VIA reads:
            ├── IDENTITY.md, SOUL.md, OBJECTIVES.md  (canonical)
            ├── personas/xyra/log/positions.jsonl    (recent stance)
            ├── personas/ora/log/positions.jsonl     (recent stance)
            ├── life/digest/since-last-turn.md       (what changed)
            └── affect/mood.json                     (current voice)
            │
            ▼
  T+1     VIA streams response back to HUMAN (SSE)
            │
            ▼
  T+1     cowork-api appends response to life/stream.jsonl
          as {"source":"chat","kind":"via.response","text":"..."}
            │
            ▼
  T+1.5   STREAM event wakes both supervisors (subscribed to chat.*)

          ┌─────────────────────┐    ┌─────────────────────┐
          │  ORA                │    │  XYRA               │
          │  observe → think    │    │  observe → think    │
          │  act (memory.write) │    │  act (memory.write) │
          │  may open PR        │    │  may open PR        │
          └──────────┬──────────┘    └──────────┬──────────┘
                     │                          │
                     └──────────┬───────────────┘
                                ▼
  T+5     if PR opened: other supervisor reviews
            │
            ▼
  T+6     consensus job commits to canonical (or archives)
            │
            ▼
  T+next  next user turn: VIA reads updated canonical
          (the change is now part of who she is)

4. What lives on disk

~/xo-projects/via/                ← Via (a persona)
│
├── meta.json                     {parent: null, children: ["xyra","ora"]}
├── IDENTITY.md · SOUL.md · OBJECTIVES.md · USER.md · ROLE.md · AGENTS.md
│
├── life/                         what she perceives
│   ├── stream.jsonl              append-only event log
│   ├── sources/                  chat, ticker, observation, calendar...
│   ├── subscriptions/            per-persona filters
│   └── digest/                   pre-computed "since last turn"
│
├── affect/                       her feelings (mood + per-entity)
├── objectives/                   her direction (active + archived)
├── memory/                       semantic · episodic · procedural · working
├── cognition/                    thoughts · views · opinions
├── knowledge/                    world model
├── skills/                       what she can do
│
├── consensus/                    where her sub-personas negotiate
│   ├── proposals/                open PRs
│   ├── decisions/                committed PRs (with vote record)
│   └── debates/                  rejected / full transcripts
│
├── personas/                     her sub-personas (recursive)
│   │
│   ├── xyra/                     a full persona, same shape
│   │   ├── meta.json             {parent: "via", runtime: "openclaw"}
│   │   ├── IDENTITY · SOUL · ROLE · ...
│   │   ├── life/ memory/ cognition/ affect/ ...
│   │   ├── log/positions.jsonl   ← what she tells Via
│   │   └── parent-image/         ← her working model of Via (her "branch")
│   │
│   └── ora/                      another full persona
│       └── (same shape as xyra)
│
└── .xo/                          cowork-api side-state
    ├── project.json
    └── sessions/sessionslist.json

Three things to notice:

  • Every persona has the same shape. Via, Xyra, Ora are all complete. Nesting creates the hierarchy.
  • Identity is at the root, not under .xo/. Agents can read/write it; the watcher only owns .xo/.
  • Each sub-persona carries a parent-image. That's her local working copy of Via. When it diverges enough, she opens a PR.

6. Invariants (these are always true)

  • Customers only talk to Via. Xyra and Ora never emit to the human surface. Their output goes to their own logs or to consensus/proposals/.
  • Only consensus writes to canonical Via. No sub-persona can change IDENTITY.md, SOUL.md, or OBJECTIVES.md on her own.
  • Every identity change has a paper trail. PR with diff, rationale, evidence (action IDs), review vote, commit decision. You can ask "why does Via think X?" and follow the chain.
  • The watcher owns .xo/. Agents read it through cowork-api endpoints. They never write directly.
  • Every persona has the same folder shape. Promote, demote, fork: structural moves never change the template.
