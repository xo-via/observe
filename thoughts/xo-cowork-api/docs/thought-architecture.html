The substrate

A thought has four core qualities: purpose, DNA, about, governance. Space is the folder. Time is the layer on top.

Every thought begins with a founder, a name, a purpose, and a contract for how it can evolve. It lives in a folder. Its DNA describes its shape. Its README explains its current self. Its governance rules say how it grows or dies.

The folder is space (what is). Time is captured separately, through state, activity, milestones, and governance rules.

1. What every thought is born with

The minimum legal thought has these eleven pieces. Some live in xo.json, some are their own files.

3. The minimum thought, on disk

~/xo-thoughts/<id>/
├── xo.json             the DNA
├── PURPOSE.md          why I exist
├── README.md           current state
├── CONTRIBUTION.md     governance contract
├── TIMELINE.md         milestones (append-only)
├── (content files)     the actual substance, grows over time
└── .git/               git history (every change ever made)

Five files plus a git folder. That's the bedrock. Everything else is grown content.

4. Space vs Time (the question you asked)

Space is the folder. What files exist, what shape, who's inside, what content is there. Static. Inspectable. The xo.json + files capture this perfectly.

Time is not in the folder structure. Time has to be captured separately. Four mechanisms together do it.

The four time mechanisms

1. State

A discrete label for where the thought is in its life right now. Recorded in xo.json.state.current. Updated by a daemon based on rules.

Examples: active, stable, idle, stale, dying, dead, archived.

2. Activity

Quantitative time signals: how often it's touched, how many contributors, how recent. Computed from git log. Recorded in xo.json.activity.

Examples: commits_last_7d, unique_authors_last_30d, age_days, idle_days, velocity.

3. Milestones

The significant moments in the thought's life. Append-only to TIMELINE.md. Human-readable. Auto-emitted on major events (birth, first child, promotion, first PR, death).

Examples: "born", "first sub-thought", "promoted to persona", "first identity PR", "marked stable".

4. Governance rules

Time-based rules written in CONTRIBUTION.md. Tells the system when to transition state, when to alert, when to die. Daemons read and enforce.

Examples: "review every 30 days", "warn if idle 60+ days", "auto-archive after 90 days idle unless owner extends".

How they work together

   ┌─────────────────────────────────────────────────────────────┐
   │                                                             │
   │   git log  ──────────────▶  ACTIVITY                        │
   │   (raw events)              (commits/week, authors, idle)   │
   │                                  │                          │
   │                                  ▼                          │
   │   CONTRIBUTION.md  ──────▶  RULES                           │
   │   (governance contract)     ("idle 90d? auto-archive")      │
   │                                  │                          │
   │                                  ▼                          │
   │                              STATE (in xo.json)             │
   │   ─────────────────────────  active / stable /              │
   │   updated by a daemon        idle / stale / dying / etc.    │
   │                                  │                          │
   │                                  ▼                          │
   │   significant transitions   →  TIMELINE.md                  │
   │   (born, promoted,             (append-only milestones)     │
   │   marked-stable, archived)                                  │
   │                                                             │
   └─────────────────────────────────────────────────────────────┘

Together they answer: "What was this thought like a week ago?" (git checkout). "How fast is it changing right now?" (activity). "When did it become a persona?" (milestones). "Should it still be alive?" (governance rules applied to state + activity).

5. The state machine

Active
touched within 7 days
Stable
complete; intentionally finished
Idle
8 to 30 days
Stale
31 to 60 days
Dying
61 to 90 days, flagged
Dead
90+ days, no response
Archived
moved to legacy; read-only

                  ┌─────────┐
                  │ ACTIVE  │ ◀──────── (any commit resurrects to here)
                  └────┬────┘
                       │ owner marks complete
                       ▼
                  ┌─────────┐
                  │ STABLE  │
                  └─────────┘   ← stays here as long as referenced

   ── decay path (default if not marked stable) ────────────────────

                  ACTIVE
                    │ no commit for 7 days
                    ▼
                  IDLE   (no warning; healthy pause)
                    │ no commit for 30 days
                    ▼
                  STALE  (gentle warning to owner)
                    │ no commit for 60 days
                    ▼
                  DYING  (loud warning; flagged for review)
                    │ no commit + no response from owner for 90 days
                    ▼
                  DEAD
                    │
                    │ daemon archives based on governance rule
                    ▼
                  ARCHIVED  (state preserved, runtime stopped)

   ── any state can be revived ────────────────────────────────────

                  any state ──── commit ────▶ ACTIVE
                  archived ──── owner unarchives ────▶ ACTIVE

Thresholds (7, 30, 60, 90 days) are defaults declared in CONTRIBUTION.md. Per-thought overrides allowed. A thought can also opt out entirely ("lifespan": { "never_decays": true }) if it's a permanent fixture.

7. CONTRIBUTION.md (the governance contract)

This is where the thought declares its rules. Read by humans and the daemon.

# Via, contribution and governance

## Who can contribute
- Owner (suraj): full read/write
- Sub-personas (xyra, ora): write to consensus/proposals/ only
- All other thoughts: read-only (need fork to modify)

## What requires review
- IDENTITY.md changes: PR + unanimous consensus from sub-personas
- SOUL.md changes: PR + unanimous consensus
- Memory writes: simple majority
- Skill graduation: simple majority

## Lifespan
- Review every 30 days (calendar event auto-created)
- Warn owner if idle 60+ days
- Auto-archive after 90 days idle, unless owner has extended via review
- Owner can extend lifespan indefinitely by committing a review note

## Death and resurrection
- Archive moves folder to ~/xo-thoughts/_archive/via/
- State preserved, runtime stopped
- Lineage links remain valid (sub-personas point back here)
- Owner can unarchive at any time; resets state to "active"

## Form transitions
- This thought is currently form: persona
- Demotion to "stem" allowed only by owner with reason
- Promotion to "legacy" allowed by daemon after archive

9. What this gives you

  • Every thought has a purpose, on day one. No anonymous folders. Always answerable: why does this exist?
  • The folder tells you what is; the daemon tells you what's now. Space and time are cleanly separated. Inspecting a folder gives you state; inspecting state tells you where it is in life.
  • Death is real but gentle. Decay is gradual (idle → stale → dying → dead → archived). Owner gets warnings. Reviving is one commit.
  • Governance is per-thought. Every thought declares its own contract. A permanent fixture opts out of decay. A short-lived experiment opts into fast death.
  • History is universal. Git captures every change. Milestones capture the meaningful ones. Both stay forever.
  • The persona system fits inside. Via is a thought with form: persona. Her decay rules are "never_decays: true". Her sub-personas inherit the same shape.

10. Open questions

  • Who runs the daemon? A cowork-api background task that walks ~/xo-thoughts/ nightly? A git hook on every commit? Both?
  • What counts as "touched"? Any commit by anyone? Or only commits that change content (not auto-updates to xo.json)? Probably: only human/agent-authored commits reset idle_days.
  • How are warnings delivered? Email? Stream events? Persona observation events that wake the owner-persona? All of the above?
  • Inherited lifespan. Does a sub-thought inherit the parent's lifespan rules by default, or does each one declare its own?
  • Resurrection cost. If a dead thought is revived after a year, does it lose its history? (Git says no; xo.json could reset.) Should there be a record of how many times it died and came back?
  • Citations and dead thoughts. If thought A cites archived thought B, what happens? Stale link? Auto-update? Force-restore B?
The substrate. Folder + xo.json + PURPOSE + README + CONTRIBUTION + TIMELINE = a thought. Git history = the past. State + activity + governance = the present and future. The persona-architecture page describes one mature form (persona) sitting on top of this substrate.
