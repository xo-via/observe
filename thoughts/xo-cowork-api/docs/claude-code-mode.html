xo-cowork-api

Claude Code mode: how it works

An interactive guide to the claude_code adapter in xo-cowork-api. Covers terminology, runtime architecture, the chat dispatch flow, every endpoint your frontend will touch, and copy-paste curl recipes.

Base URL: http://localhost:5002 Auth: none locally Stage: beta

What is "Claude Code mode"?

The path in cowork-api where the user's local claude CLI runs each chat turn as a subprocess. cowork-api hands it a project folder to work in, a session id, the conversation prompt (optionally prefixed with a skill), and optional MCP servers to attach. It streams the output back over Server-Sent Events.

Trigger

POST /api/chat/prompt with agent_name: "claude_code". On resume, omit it; the dispatcher reads the session's recorded backend.

Process

cowork-api spawns the local claude binary per turn. cwd is ~/xo-projects/<agent_id>/. Permission mode is bypassPermissions by default. The CLI uses your existing Claude login on the host machine.

Streaming

Subprocess emits JSONL lines on stdout. The adapter parses and normalizes them into text-delta, session-created, heartbeat, and done SSE events. Frontend consumes via EventSource.

What you get

  • The user's local Claude install, login, and on-disk tools do the work.
  • Per-turn cwd means file edits, reads, and commands stay scoped to one project.
  • Per-session MCP configs (Composio, Vercel, GitHub) wired at --mcp-config: no long-running gateway, no global tool pollution.
  • Claude-native skills via /skill-name prefix when a frontend passes agent_type.

Project terminology

These show up everywhere. Get them right once and the rest of the API is easy.

Projects: the unit Claude Code operates on

project core

A folder under ~/xo-projects/<id>/. Backend-agnostic by design: it is just a directory plus a small metadata sidecar. Claude Code launches against one project at a time and treats that directory as the subprocess cwd. Everything Claude Code reads, writes, or runs is rooted here.

Scaffold via POST /api/files/mkdir with scaffold:true. List via GET /api/agents (each agent corresponds to a project folder).

XO project: what's inside

A scaffolded project has a canonical layout. Top-level files are the operating contract Claude Code reads first; .xo/ is the cowork-api side-state.

~/xo-projects/<id>/
├── AGENTS.md         universal operating contract
├── OBJECTIVES.md     north-star outcomes
├── WORKSPACE.md      current state of play
├── CLAUDE.md         one-line pointer to AGENTS.md
└── .xo/
    ├── project.json  {name, display_name, description, created_at}
    ├── sessions/     sessionslist.json + compressed/ + index.md
    ├── memory/       semantic / episodic / procedural / working
    ├── artifacts/    drafts/ + final/
    ├── state/        SOUL.md, STATUS.md, IDENTITY.md, USER.md
    ├── skills/       user-built / learned
    └── context/      config.json, cache.md

Scaffolding is idempotent: re-running fills in missing pieces, never clobbers. .xo/ is owned by cowork-api's watcher; agents must not write to it directly.

agent_id important

The string that names a project. Used in three places:

  • As the folder name: ~/xo-projects/<agent_id>/.
  • As the subprocess cwd when Claude Code spawns.
  • As the session-index key in ~/xo-projects/<agent_id>/.xo/sessions/sessionslist.json.

Naming rules

Regex: ^[a-z0-9][a-z0-9_-]{0,63}$. Lowercased on input. Invalid chars rewrite to -; leading/trailing dashes stripped; max 64 chars.

Resolution from workspace path

If you omit agent_id on a new turn but pass workspace:

workspace: /Users/me/xo-projects/blackhole/src
  → agent_id auto-resolves to "blackhole"

workspace: /Users/me/somewhere-else
  → agent_id is null; turn still runs but no project-side metadata is written

xo-projects root

Discovery first call: GET /api/config/workspace returns {roots, default}. The default points to ~/xo-projects on a laptop and /home/coder/xo-projects in a Coder workspace. Never hard-code; container hosts differ.

Override the root via $XO_PROJECTS_ROOT if you need a non-default location.

Per-turn concepts

agent_type

Optional skill name for the turn. cowork-api maps it to /skill-name and prefixes the user prompt with it. Example: agent_type: "research" becomes prompt prefix /research. The skill itself lives in .claude/skills/research/SKILL.md (workspace-level) or ~/xo-projects/<id>/.xo/skills/<name>/SKILL.md (project-level).

skill

A Claude-native skill: a folder containing SKILL.md defining behavior, allowed tools, and any embedded resources. Invoked by prefixing a prompt with /<name>. cowork-api auto-installs the bundled xo-projects skill into ~/.claude/skills/xo-projects/ on startup.

session_id

UUID identifying a logical conversation. cowork-api owns it; the Claude CLI's internal conversation id may be different. Generated synchronously by /api/chat/prompt: the response carries it back before tokens flow, so the frontend can navigate to /c/<session_id> immediately.

stream_id

Per-turn UUID returned by /api/chat/prompt. Used as the path param on GET /api/chat/stream/{id} and POST /api/chat/abort. Single use; lives in memory only. Lost on server restart.

workspace

Absolute project path. Alternative to agent_id when starting a new session: if workspace begins with ~/xo-projects/<X>/, agent_id auto-resolves to X and the subprocess cwd is the full workspace path.

MCP server

An external tool server (Composio, Vercel, GitHub, the local /mcp/cowork). Claude Code consumes MCP servers via a per-session --mcp-config file written by the adapter at turn start. The frontend doesn't pick servers; the adapter selects based on which connectors the user has connected.

dispatcher

Internal cowork-api layer that owns the Claude Code chat flow. On GET /api/chat/stream/{id} it pops the reserved stream_id, spawns the claude subprocess with the right cwd, --session-id, and --mcp-config, parses the JSONL stdout, and emits SSE events.

auth_state

In-memory dict cowork-api uses to talk to upstream xo-swarm-api. Populated by the Clerk poll-token flow at /xo-auth/consume or by $XO_API_KEY. Frontends never see this token; it's used only for outbound calls.

Watcher rule. The .xo/ directory is owned by cowork-api's watcher service. Agents (including Claude Code) must not write into it directly. Treat it as read-only from the agent's side.

Auth model

  • Inbound to cowork-api: no auth required at the routes you'll call as a frontend. The workspace is the trust boundary.
  • Outbound to swarm: cowork-api carries a bearer token from /xo-auth/consume (Clerk poll-token flow) or $XO_API_KEY.
  • Outbound to connectors: credentials live in mcp-tokens.json. Composio is the exception: Composio's hosted dashboard is the source of truth.

The two-step turn

Every chat turn is exactly two HTTP calls. The split lets the frontend navigate to /c/<session_id> before any tokens arrive.

  Client                       cowork-api                          claude CLI
    │                              │                                   │
    │ POST /api/chat/prompt        │                                   │
    │ {text, agent_name, agent_id} │                                   │
    │ ───────────────────────────▶ │                                   │
    │                              │ active_streams[stream_id] = info  │
    │ {stream_id, session_id}      │                                   │
    │ ◀─────────────────────────── │                                   │
    │                              │                                   │
    │ GET /api/chat/stream/<id>    │                                   │
    │ ───────────────────────────▶ │ pop entry, spawn dispatcher       │
    │                              │ ────────────────────────────────▶ │ subprocess
    │                              │ ◀──────────────────────────────── │ JSONL stdout
    │ event: session-created       │                                   │
    │ ◀─────────────────────────── │                                   │
    │ event: text-delta            │                                   │
    │ ◀─────────────────────────── │                                   │
    │ event: text-delta            │                                   │
    │ ◀─────────────────────────── │                                   │
    │ event: heartbeat (idle >20s) │                                   │
    │ ◀─────────────────────────── │                                   │
    │ event: done                  │                                   │
    │ ◀─────────────────────────── │                                   │
    │ (server closes stream)       │                                   │

SSE event vocabulary

EventDataWhen
session-created{session_id}Once at the start of a new-session turn.
text-delta{text}Many. Accumulate into the assistant message.
heartbeat{}Every 20s of silence (Claude Code path). Keep-alive; do not render.
agent-error{error_message}Terminal. No done follows.
done{finish_reason, session_id}Once at the end of a successful turn. Server closes after.
error{error_message}Only for an unknown / expired stream_id.
Heartbeat is keep-alive only. Reset your dead-stream timer when you see one. Recommended client timeout: 45s (about 2x the longest gap).

Reconnect within 600s

If a client opens the stream, navigates away, and re-opens it within 600 seconds, the second GET on the same stream_id enters reconnect mode: it does not start a new turn. It waits for the original to finish (up to 300s), then emits session-created + done, both without any text-delta. The frontend should refetch via GET /api/messages/{session_id} to recover the tokens it missed.

Endpoints you'll call

Grouped by the order you'll typically use them. Click any endpoint to expand.

1. Boot / discovery

GET /api/config/workspace

Discover the projects root. Always call this on boot.

curl -s http://localhost:5002/api/config/workspace
# {
#   "roots":  { "default": "/Users/me/xo-projects" },
#   "default": "default"
# }

Read cfg.roots[cfg.default] as your project root. Never hard-code ~/xo-projects; containers use /home/coder/xo-projects.

GET /api/agents

List projects under ~/xo-projects/. Use to populate a project picker.

curl -s http://localhost:5002/api/agents
# {"agents": [{"id": "blackhole", "backend": "claude_code", ...}]}
GET /api/models

List models the local claude CLI exposes. Surfaces what the UI can offer.

2. Chat

POST /api/chat/prompt

Reserve a turn. Returns {stream_id, session_id}.

curl -s -X POST http://localhost:5002/api/chat/prompt \
  -H "Content-Type: application/json" \
  -d '{
    "text":       "Refactor the auth flow to use the new Clerk SDK",
    "agent_name": "claude_code",
    "agent_id":   "blackhole",
    "agent_type": "research"
  }'
# {"stream_id": "8f3a...", "session_id": "9d4e..."}

Body fields

FieldTypeNotes
textstringRequired. Empty after trim returns 400.
session_idstringOptional. Set to resume; omit for a new session.
agent_namestringSet to "claude_code". Auto-detected from the session record on resume, so you may omit it then.
agent_idstringProject folder under ~/xo-projects/. Becomes cwd for the claude subprocess.
agent_typestringSkill name. Prompt is prefixed with /<skill-name>.
workspacestringAbsolute path. Alternative to agent_id for new sessions.
SSE /api/chat/stream/{stream_id}

Open the SSE stream for the reserved stream_id. Single use.

curl -N http://localhost:5002/api/chat/stream/8f3a-...
# id: 1
# event: session-created
# data: {"session_id":"9d4e..."}
#
# id: 2
# event: text-delta
# data: {"text":"Sure","session_id":"9d4e..."}
# ...
# id: N
# event: done
# data: {"finish_reason":"stop","session_id":"9d4e..."}

From a browser, use EventSource:

const es = new EventSource(`/api/chat/stream/${stream_id}`);
es.addEventListener("session-created", e => {
  const { session_id } = JSON.parse(e.data);
  history.pushState(null, "", `/c/${session_id}`);
});
es.addEventListener("text-delta", e => {
  const { text } = JSON.parse(e.data);
  buffer += text;
  render(buffer);
});
es.addEventListener("done", () => es.close());
es.addEventListener("agent-error", e => {
  const { error_message } = JSON.parse(e.data);
  showError(error_message);
  es.close();
});
POST /api/chat/abort

Drop an in-flight stream by id. Always returns 200.

curl -s -X POST http://localhost:5002/api/chat/abort \
  -H "Content-Type: application/json" \
  -d '{"stream_id":"8f3a-..."}'

3. Sessions and messages

GET /api/sessions

List Claude Code sessions. Use for the sidebar. Each row carries session_id, agent_id (project), title, and timestamps.

curl -s "http://localhost:5002/api/sessions?limit=20"
GET /api/messages/{session_id}

Read history for a session. Supports paging with offset and limit. offset=-1 means "newest page" (the default).

curl -s "http://localhost:5002/api/messages/9d4e...?limit=50"

Each message has role, content, and a timestamp. Tool calls and tool results are surfaced inline.

4. Files (workspace IO)

GET /api/files/list-directory 
curl -s "http://localhost:5002/api/files/list-directory?path=/Users/me/xo-projects/blackhole"

Path is clamped to $HOME; outside returns 403.

GET /api/files/content

Read a text file. Use /api/files/content-binary for binary.

POST /api/files/save

Write a text file (also creates parent dirs).

POST /api/files/mkdir

Create a directory. Pass scaffold:true to bootstrap a new project under ~/xo-projects/<id>/.

5. Connectors (MCP servers)

GET /api/connectors/composio/toolkits early access

List Composio toolkits and per-user connection status. Requires COMPOSIO_API_KEY + per-toolkit COMPOSIO_AUTH_CONFIG_*.

POST /api/connectors/composio/{toolkit}/connect early access

Kick off the OAuth or API-key flow. OAuth response: {auth_url, connection_request_id}.

GET /api/connectors/{vercel,github,manus,gdrive,onedrive}/...

Each non-Composio connector has its own connect / status / disconnect / reconnect routes. See the connectors guide for the full surface.

6. Local MCP mount

MCP /mcp/cowork

A Streamable-HTTP MCP server cowork-api exposes to itself and to the Claude Code adapter. Surfaces two meta-tools: composio_list_tools and composio_execute. Net effect: instead of carrying every Composio action of every connected toolkit, the gateway carries 2 tools that fetch / dispatch on demand.

Not for direct frontend consumption. Requires an MCP-aware client that sends Accept: text/event-stream.

7. Server lifecycle

GET /health 
curl -s http://localhost:5002/health
POST /app/restart

Trigger a managed restart. Combine with ./cowork-api.sh restart when running locally for a clean stop.

Copy-paste recipes

All recipes assume the server is up on http://localhost:5002.

Recipe 1: render a chat UI

// 1. On boot, discover the projects root.
const cfg = await fetch("/api/config/workspace").then(r => r.json());
const projectsRoot = cfg.roots[cfg.default];

// 2. Populate sidebar.
const { sessions } = await fetch("/api/sessions?limit=50").then(r => r.json());

// 3. When user picks a session, load history.
async function loadSession(session_id) {
  const { messages } = await fetch(`/api/messages/${session_id}`).then(r => r.json());
  return messages;
}

// 4. On submit, reserve a turn.
async function sendTurn({ text, session_id, agent_id, agent_type }) {
  const r = await fetch("/api/chat/prompt", {
    method:  "POST",
    headers: { "Content-Type": "application/json" },
    body:    JSON.stringify({
      text, session_id, agent_id, agent_type,
      agent_name: "claude_code",
    }),
  });
  if (!r.ok) throw new Error((await r.json()).detail);
  return r.json();  // {stream_id, session_id}
}

// 5. Open the SSE stream.
function openStream({ stream_id, onText, onDone, onError }) {
  const es = new EventSource(`/api/chat/stream/${stream_id}`);
  es.addEventListener("session-created", e =>
    onText({ kind: "session", data: JSON.parse(e.data) }));
  es.addEventListener("text-delta", e =>
    onText({ kind: "delta", data: JSON.parse(e.data) }));
  es.addEventListener("agent-error", e => {
    onError(JSON.parse(e.data).error_message);
    es.close();
  });
  es.addEventListener("done", () => { onDone(); es.close(); });
  return () => es.close();
}

Recipe 2: start a project, then chat about it

# 1. Scaffold a new project folder.
curl -s -X POST http://localhost:5002/api/files/mkdir \
  -H "Content-Type: application/json" \
  -d '{"path":"/Users/me/xo-projects/blackhole","scaffold":true}'

# 2. Open a Claude Code turn that operates inside it.
RESP=$(curl -s -X POST http://localhost:5002/api/chat/prompt \
  -H "Content-Type: application/json" \
  -d '{"text":"Bootstrap a Next.js 16 app here","agent_name":"claude_code","agent_id":"blackhole"}')
STREAM_ID=$(echo "$RESP" | jq -r .stream_id)

# 3. Tail the SSE stream.
curl -N "http://localhost:5002/api/chat/stream/$STREAM_ID"
