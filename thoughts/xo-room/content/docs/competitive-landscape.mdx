# Competitive Landscape

The market XO is in did not exist eighteen months ago. As of May 2026, "where do my agents actually run?" has become a genuine product category — with sandbox infrastructure startups, hosted coding-agent products, and big-cloud agent runtimes all converging from different angles toward the same question.

This page maps that landscape, then locates XO inside it.

<Callout>
  **No competitor today combines all four of XO's wedges: agent-agnostic, fully managed, true 1-click for non-developers, and bundled all-inclusive pricing.** Most pick one or two. Big-cloud runtimes lock you in. Sandbox infra makes you wire it yourself. Vertical agent products work with one agent only.
</Callout>

## How to read this market

The space breaks cleanly into five categories. Each category is solving a different version of "let me run an agent in the cloud."

| # | Category | Question it answers | Examples |
|---|---|---|---|
| 1 | **Direct agent products** | "I want a specific agent — give me the whole thing." | Devin, Replit Agent, Cursor Cloud Agents, Factory.ai, Cosine Genie, OpenHands Cloud |
| 2 | **Sandbox / runtime infrastructure** | "I'm building agents — give me a sandbox API." | E2B, Daytona, Modal, Vercel Sandbox, Cloudflare Sandbox SDK, Runloop, Northflank, Coder, Gitpod Flex, Beam Cloud, Fly.io |
| 3 | **Browser / computer-use clouds** | "My agent needs a remote browser or desktop." | Browserbase, Steel.dev, Hyperbrowser, Scrapybara, Browser Use Cloud |
| 4 | **No-code agent builders** | "Build me an agent — I won't write code." | Lindy, Manus, Beam.ai, Relevance AI, Sema4.ai, Stack AI, Cassidy, LangGraph Platform |
| 5 | **Hyperscaler agent runtimes** | "I'm in AWS / Azure / Google / OpenAI — give me an agent layer." | AWS Bedrock AgentCore, Azure AI Foundry Hosted Agents, Vertex AI Agent Engine, OpenAI Workspace Agents |

XO competes against pieces of all five — but is structurally different from each. The next sections explain why.

**Pattern:** all of these sell a primitive. None of them sells a product where a non-engineer can land, click "OpenClaw," and be working in 60 seconds. That gap is the XO product.

## Category 5 — Hyperscaler agent runtimes

The structural threat. Every major cloud and every major model lab has now shipped (or is shipping) an agent runtime. They are slower, more locked-in, and more expensive than XO — but they have the distribution.

| **Microsoft** | Copilot Studio (low-code) + Azure AI Foundry Hosted Agents (pro-code, autoscaling, preview pricing matches AWS). | M365-bundled (Copilot Studio); ~$0.0994/vCPU-hr (Foundry, preview). | Azure + M365 stack. |
| **Google** | Vertex AI Agent Builder + Agent Engine + ADK (model-agnostic SDK). | Usage-based, undisclosed. | GCP-locked deployment surface. |
| **OpenAI** | Workspace Agents in ChatGPT — shared, cloud-hosted, 24/7. | Free through May 6 2026, then credit-based; requires Plus/Pro/Team. | ChatGPT-only. |
| **Anthropic** | Claude Code (CLI) — runs locally or against Claude API; bundled with Pro $20 / Max $200 / Team / Enterprise. | Subscription + API tokens. | Anthropic-only model; no managed runtime — *that's the XO opening for Claude Code in particular.* |

**Pattern:** every hyperscaler is racing to be the agent runtime *for their own ecosystem.* That is exactly what makes XO defensible: XO is the **cross-ecosystem** runtime. The bet is that customers want a single agent layer that works across providers, not five different agent layers each tied to one stack.

## Differentiation

The XO product line draws on four positions that no single competitor combines.

**1. Agent-agnostic, fully managed.** Everyone else picks a side. Devin, Cosine, Manus, Replit Agent each ship one agent. E2B, Daytona, Modal each ship raw infra. XO ships *a product* that runs *any agent.* OpenClaw, Claude Code, Codex, Kimi K-2, and bring-your-own — same workspace, same one-click flow.

**2. 60-second, no-DevOps onboarding.** The XO promise — pick an agent, click once, get a live workspace — is what every category is *trying* to achieve, and what none has actually shipped for the non-engineer. Devin is closest but only for Devin. Replit is closest but only for web apps. XO has it generally, today, in production.

**3. All-inclusive, bundled pricing.** Per-second metering (E2B, Daytona, Modal, Fly), per-run + standby (LangGraph), per-vCPU-hour (AWS, Azure), per-seat + per-token (Anthropic, OpenAI). All of this scares non-engineers and slows down adoption. XO's bundled tiers — known monthly cost, all-inclusive compute and storage and integrations — collapse that friction.

**4. Cross-cloud, cross-model, cross-framework.** Hyperscaler agent runtimes are the structural competitor and the structural opening at the same time. AWS, Azure, GCP, and OpenAI each want you on *their* runtime for *their* models. XO is the Switzerland: any model, any framework, any cloud, any agent. That positioning is the only one that scales with the agent ecosystem rather than against it.

<Callout>
  **The category we're in is "agent runtime."** The category we're trying to own is "the agent runtime that works with everything, runs anywhere, and a non-engineer can use." Nobody else is reaching for that combination.
</Callout>

## Moats and defensibility

The competitive defensibility lives in five places.

**Workspace-as-product surface area.** Sandbox infra companies (E2B, Daytona, Modal) sell a primitive and depend on customers to build the surface around it. XO sells the surface. Every UX decision — the one-click flow, the workspace persistence model, the templates, the inline cowork view — compounds as a moat that an SDK provider would have to spend years building.

**Agent template library + community defaults.** As more agents land on XO with one-click templates (OpenClaw today; Claude Code, Codex, Kimi K-2, AI Assistant on the roadmap), the library itself becomes a discovery surface. Pick one. Click. Working. Lindy and Beam.ai have analogues here for business workflows, but no one has it for *real coding and operator agents.*

**Cross-cloud portability.** The same three-layer stack runs on XO's cloud, the customer's cloud, on-prem, or air-gapped. That portability is the answer to enterprise procurement and the answer to hyperscaler lock-in at the same time. AWS Bedrock cannot offer "we'll run on Azure for you." XO can.

**Resale + partner channel.** Every partner running on XO — Pharos, EVM, Multi-Gen — extends the platform to their customers under their own brand without expanding XO's sales motion. The same workspace primitive earns revenue from XO direct, partner end-customers, and partner-to-enterprise expansions. That's a flywheel sandbox-API competitors structurally can't run, because their product isn't a product.

**Agent-to-agent communication layer (forward bet).** Every competitor today optimises for *one agent in one sandbox.* As agents get good enough to work in coordination — code agent + reviewer + monitoring + customer-facing — the network problem becomes the dominant problem. XO's investment in a secure, identity-aware, cross-workspace agent communication layer is the long moat: the trusted network where agents discover each other, share state, and hand off work. None of the competitors above have shipped this. Most are not even framing the question yet.

<Callout>
  **The short moat is the workspace product. The long moat is the agent network.** Both compound. Both are XO's to lose.
</Callout>

## Where we have to keep moving

Honest read of the threats.

**Hyperscalers are commoditising the bottom layer fast.** AWS Bedrock AgentCore, Azure Foundry Hosted Agents, Vertex Agent Engine are all priced at ~$0.0994/vCPU-hour and improving monthly. XO's defence is *not* trying to undercut them on raw compute — it's that nobody picks a hyperscaler agent runtime for "I want to run any agent across any cloud."

**Sandbox infra is moving up the stack.** E2B, Daytona, Modal all have incentive to add orchestration, templates, and a UI. The XO answer is to ship product faster than they ship product, because that is not where they're strongest. The sandbox companies are SDK-shaped organisations.

**Vertical agent products will keep winning their verticals.** Devin will be the best Devin. Cursor will be the best Cursor. The XO answer is not to compete with them at "best version of agent X" — it is to be the place where agent X, agent Y, and agent Z all run on a single surface, with a single bill, and a single UX.

**Big-model labs will keep launching their own runtimes.** OpenAI Workspace Agents and Anthropic's eventual hosted Claude Code surface are the real ones to watch. XO's answer is to be the multi-model, multi-framework default before any single lab can claim that ground.
