OpenClaw isn't just another AI chatbot wrapper. It's a **multi-agent gateway** that can host completely isolated AI "brains," each with its own workspace, memory, credentials, and tool permissions—all running on a single server.

This guide breaks down the two core concepts that make OpenClaw powerful: **Agents** and **Sessions**.

## What is an Agent?

<div className="my-8 p-5 bg-sky-950/30 border-l-4 border-sky-500 rounded-r-lg">
  <div className="font-bold text-sky-400 mb-2">FULLY ISOLATED</div>
  <div className="text-neutral-300">An agent is a complete AI "brain" with its own workspace, credentials, sessions, tool permissions, and memory. Think of agents as separate employees—each with their own desk, files, and access badges.</div>
</div>

Each agent has:

| Component | Description |
|-----------|-------------|
| **Workspace** | Files, AGENTS.md, SOUL.md, USER.md, memory |
| **Agent Dir** | Auth profiles, per-agent config |
| **Session Store** | Chat history, session metadata |
| **Model** | Which LLM to use |
| **Tool Policy** | Which tools are allowed/denied |
| **Sandbox** | Isolation settings |

### Agent Configuration

Agents are defined in `openclaw.json`:

```json
{
  "agents": {
    "defaults": {
      "model": { "primary": "anthropic/claude-opus-4-5" },
      "workspace": "~/.openclaw/workspace"
    },
    "list": [
      {
        "id": "main",
        "default": false,
        "workspace": "~/.openclaw/workspace",
        "sandbox": { "mode": "off" }
      },
      {
        "id": "public",
        "default": true,
        "workspace": "~/.openclaw/workspace-public",
        "tools": {
          "allow": ["read", "web_search", "message"],
          "deny": ["exec", "write", "gateway"]
        }
      }
    ]
  }
}
```

## What is a Session?

A **session** is a conversation thread. It contains:

- **Session ID**: Unique identifier (UUID)
- **Session Key**: Human-readable routing key
- **Transcript**: JSONL file with all messages and tool calls
- **Context**: The rolling window sent to the LLM
- **Metadata**: Token counts, model, timestamps

<div className="my-8 p-5 bg-emerald-950/30 border-l-4 border-emerald-500 rounded-r-lg">
  <div className="font-bold text-emerald-400 mb-2">SESSION vs CONTEXT</div>
  <div className="text-neutral-300"><strong>Session</strong> = full history (stored in JSONL). <strong>Context</strong> = what's actually sent to the LLM (limited by context window). When context fills up, OpenClaw can compact older messages into a summary.</div>
</div>

### Session Keys

Session keys follow a pattern based on your `dmScope` setting:

| dmScope | Session Key Pattern | Behavior |
|---------|---------------------|----------|
| `main` | `agent:<agentId>:main` | All DMs share one session |
| `per-peer` | `agent:<agentId>:dm:<peerId>` | Isolate by sender |
| `per-channel-peer` | `agent:<agentId>:<channel>:dm:<peerId>` | Isolate by channel + sender |

**Groups always get isolated sessions:** `agent:<agentId>:<channel>:group:<groupId>`

### Example Session Keys

```
agent:main:whatsapp:dm:alice        # Admin's WhatsApp DM
agent:main:webchat:dm:alice         # Admin's webchat (same person, different channel)
agent:public:whatsapp:dm:+15551234  # Random user's WhatsApp DM
agent:public:telegram:group:123456  # A Telegram group
```

## Bindings: The Routing Layer

**Bindings** map incoming messages to agents. They use a **most-specific-wins** strategy.

```json
{
  "bindings": [
    {
      "agentId": "main",
      "match": {
        "channel": "whatsapp",
        "peer": { "kind": "dm", "id": "+15551234567" }
      }
    },
    {
      "agentId": "main",
      "match": {
        "channel": "webchat",
        "peer": { "kind": "dm", "id": "+15551234567" }
      }
    }
  ]
}
```

## Identity Links: Cross-Channel Continuity

What if you want the **same person** to share a session across channels? Use **identity links**:

```json
{
  "session": {
    "identityLinks": {
      "alice": [
        "whatsapp:+15551234567",
        "webchat:+15551234567"
      ]
    }
  }
}
```

Now when a message comes from `whatsapp:+15551234567`, the canonical ID becomes `alice`, so both WhatsApp and webchat use the same session.

<div className="my-8 p-5 bg-violet-950/30 border-l-4 border-violet-500 rounded-r-lg">
  <div className="font-bold text-violet-400 mb-2">SAME CONVERSATION, ANY DEVICE</div>
  <div className="text-neutral-300">With identity links, you can start a conversation on WhatsApp and continue it on webchat seamlessly. The agent remembers everything across channels.</div>
</div>

## Sandbox & Tool Restrictions

OpenClaw supports **per-agent sandboxing** and tool policies for security:

### Sandbox Modes

| Mode | Description |
|------|-------------|
| `off` | No sandbox, full host access |
| `non-main` | Sandbox non-main sessions only |
| `all` | Sandbox all sessions |

### Tool Policies

Tools can be restricted at multiple levels:

```json
{
  "agents": {
    "list": [
      {
        "id": "public",
        "tools": {
          "allow": ["read", "web_search", "web_fetch"],
          "deny": ["exec", "write", "edit", "gateway", "browser"]
        },
        "sandbox": {
          "mode": "all",
          "scope": "session"
        }
      }
    ]
  }
}
```

### Tool Groups (Shortcuts)

| Group | Tools Included |
|-------|---------------|
| `group:runtime` | exec, bash, process |
| `group:fs` | read, write, edit, apply_patch |
| `group:sessions` | sessions_list, sessions_history, sessions_send, sessions_spawn |
| `group:memory` | memory_search, memory_get |
| `group:ui` | browser, canvas |
| `group:messaging` | message |

## Real-World Architecture Examples

### Example 1: Personal Admin + Public Agent

```json
{
  "agents": {
    "list": [
      {
        "id": "main",
        "default": false,
        "workspace": "~/.openclaw/workspace",
        "sandbox": { "mode": "off" }
      },
      {
        "id": "public",
        "default": true,
        "workspace": "~/.openclaw/workspace-public",
        "sandbox": { "mode": "all" },
        "tools": {
          "allow": ["read", "web_search", "message"]
        }
      }
    ]
  },
  "bindings": [
    {
      "agentId": "main",
      "match": { "channel": "whatsapp", "peer": { "kind": "dm", "id": "+1ADMINPHONE" } }
    }
  ]
}
```

**Result:**
- Your phone → `main` agent (full access)
- Everyone else → `public` agent (restricted, sandboxed)

### Example 2: Channel-Based Routing

```json
{
  "agents": {
    "list": [
      {
        "id": "fast",
        "model": "anthropic/claude-sonnet-4",
        "workspace": "~/.openclaw/workspace-fast"
      },
      {
        "id": "deep",
        "model": "anthropic/claude-opus-4-5",
        "workspace": "~/.openclaw/workspace-deep"
      }
    ]
  },
  "bindings": [
    { "agentId": "fast", "match": { "channel": "whatsapp" } },
    { "agentId": "deep", "match": { "channel": "telegram" } }
  ]
}
```

**Result:**
- WhatsApp → Fast Sonnet model for quick chats
- Telegram → Opus model for deep work

### Example 3: Multi-User Family Setup

```json
{
  "agents": {
    "list": [
      { "id": "alex", "workspace": "~/.openclaw/workspace-alex" },
      { "id": "mia", "workspace": "~/.openclaw/workspace-mia" }
    ]
  },
  "bindings": [
    { "agentId": "alex", "match": { "channel": "whatsapp", "peer": { "kind": "dm", "id": "+15551230001" } } },
    { "agentId": "mia", "match": { "channel": "whatsapp", "peer": { "kind": "dm", "id": "+15551230002" } } }
  ]
}
```

**Result:**
- Each family member gets their own isolated agent
- Separate workspaces, memories, and personalities

## Session Lifecycle

### Creation
Sessions are created on-demand when a message arrives and no existing session matches.

### Reset Policies

| Policy | Description |
|--------|-------------|
| `daily` | Reset at a specific hour (default: 4 AM local) |
| `idle` | Reset after N minutes of inactivity |
| Combined | Whichever expires first |

### Manual Reset Commands

| Command | Effect |
|---------|--------|
| `/new` | Start fresh session |
| `/new opus` | New session with different model |
| `/model opus` | Switch model mid-session |
| `/model default` | Reset to default model |
| `/compact` | Summarize old context |
| `/status` | Show session info |

    </ul>
